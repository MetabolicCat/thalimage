## GEN-001: Perceptual hash pads at full resolution, memory grows with max(w,h)²

Code (`backend/src/thalimage/core/perceptual_hash.py:37-42`, from ae7f2b7):

    with Image.open(path) as img:
        rgba = img.convert("RGBA")              # w*h*4 bytes
    side = max(rgba.size)
    flat = Image.new("RGBA", (side, side), "white")   # side*side*4 bytes
    flat.alpha_composite(rgba, (...))
    grey = flat.convert("L").resize((_SIZE, _SIZE), LANCZOS)  # + side*side bytes

Before ae7f2b7, `flat` was `rgba.size`, so memory followed w*h.

Measured (Pillow in backend/.venv, a single call, ru_maxrss):

| picture     | peak RSS |
|-------------|----------|
| 1024x1024   | 43 MB    |
| 800x12000   | 778 MB   |

Extrapolated: 1000x30000 needs about 3.6 GB (RGBA square) + 0.9 GB (L copy);
1500x59000 (88.5 MP, under Pillow's 89.5 MP bomb limit) needs about 14 GB.

The scan computes this in `_index_file` (`scan_service.py:415`) for every
still. `PERCEPTUAL_HASH_VERSION = 3` makes the next scan recompute it for every
picture, and `concurrent_scans` defaults to True (`config.py:54`).

Fix sketch: shrink first, then pad at that scale, e.g.

    img.thumbnail((1024, 1024), Image.Resampling.LANCZOS)   # or reduce()
    side = max(img.size); pad onto a side x side white square; resize to 32

The resulting hash can move by a bit against today's; raise the version only
after GEN-004, or all videos are re-read again.
