## PKG-002: Declare the certifi exclude-newer exemption that uv.lock depends on

### Evidence

`git show HEAD:backend/pyproject.toml`, lines 61-63:

    [tool.uv]
    # Resolve only releases at least a week old (recorded in uv.lock).
    exclude-newer = "7 days"

`git show HEAD:backend/uv.lock`, lines 5-10 and 44-47:

    [options]
    exclude-newer = "0001-01-01T00:00:00Z" # ...
    exclude-newer-span = "P7D"

    [options.exclude-newer-package]
    certifi = false
    ...
    name = "certifi"
    version = "2026.10.19"
    ... upload-time = "2026-10-20T02:24:16.604Z"

Commit e11b62d ("Upgrade certifi past the compromised eMudhra CA roots",
Refs #170) touches only `backend/uv.lock`; `pyproject.toml` is unchanged.

certifi's only dependents in the lock are `httpcore` and `httpx`, both
reached from the `dev` dependency group (`backend/pyproject.toml:30-32`).

### Reproduction (committed tree, uv 0.13.5, scratch copy via git archive)

    $ uv lock --check
    Resolving despite existing lockfile due to removal of exclude newer for package `certifi`
    Resolved 47 packages in 14ms
    error: The lockfile at `uv.lock` needs to be updated, but `--check` was provided.

    $ uv lock --dry-run
    Resolving despite existing lockfile due to removal of exclude newer for package `certifi`
    Resolved 47 packages in 8ms
    Update certifi v2026.10.19 -> v2026.10.18

### CI (uv 0.12.22, job 121647894854, push of 4f48e65 to main)

    cd backend && uv sync
    Using CPython 3.12.3 interpreter at: /usr/bin/python3
    Resolving despite existing lockfile due to removal of exclude newer for package `certifi`
    ...
     + certifi==2026.10.18
    ...
    === Lock ===
    cd backend && uv lock --check
    Resolved 47 packages in 0.88ms

uv 0.12.22 resolves the same way as 0.13.5: the uv version is not what made
CI pass; PKG-001 is.

### Impact

- Any `make install`, `make test`, `make dev` or `uv run ...` rewrites the
  lock back to certifi 2026.10.18 and installs it; committing that lock
  undoes #171.
- The Docker image uses `uv sync --frozen` (`docker/Dockerfile:39,45`), which
  takes the lock as-is, so an image built from HEAD should carry 2026.10.19
  (inferred from `--frozen` semantics; the image was not built or inspected).
  `--frozen` also means the image build never notices a drifted lock.

### Fix

Under `[tool.uv]`:

    exclude-newer-package = { certifi = false }

(or require `certifi>=2026.10.19` directly), then `uv lock`. Remove the
exemption once 2026.10.19 is older than 7 days (after 2026-10-27); a plain
floor or nothing suffices then. Optionally switch the Dockerfile to
`--locked`.
